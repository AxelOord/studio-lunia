## Private Blob adapter and upload gate

The exact official Payload Blob adapter 4.0.0-canary.37 declares access as public-only and
its browser uploader hardcodes public. We do not enable that adapter. `src/hosting/private-blob.ts`
uses the pinned Payload cloud-storage plugin and @vercel/blob 2.8.0 private APIs. This is
application-owned integration code, not an upstream claim of private support.

Payload enforces collection read access, verifies user-bound signed upload receipts and
validates/processes files before records are finalized. Upload grants use random object-key
segments, exact MIME/size, no overwrite and ten-minute expiry. Browser bytes go directly to
Blob; only the signed reference is submitted through Payload, avoiding Vercel's upload-body
limit. Private reads stream through Payload with no-store; no presigned read URL is returned.
Client grants and reset links are secrets: never record them in logs/screenshots/traces.

Caps are 20 MiB and 40 million pixels. Raster types only; required alt text; Sharp produces
card/hero variants. Next image optimization is disabled for mutable-access media so it cannot
serve a formerly public image after revocation. Page blocks use stored size variants.

Before hosted activation prove: direct upload and CORS in a real browser; no anonymous
provider URL access; private original/card/hero reads denied; allowed reads succeed; public
then private becomes denied including cache/optimizer paths; oversized/malformed files fail;
interrupted requests leave no published record; a redeploy preserves all bytes. Local SDK
mocks do not prove provider ACLs, CORS, network latency, or execution-time limits.

Failed direct uploads and successfully converted source files can leave PRIVATE unreferenced
objects. Local tests confirm that this remains an operational gap, not automatic cleanup.
`npm run preview:inventory --
/path/to/new-manifest.json` produces a mode-0600 read-only manifest of Blob hashes and
references from media plus media versions. It reports missing references and orphan
candidates without deleting anything. Review objects older than 24h only after quiescing
writes and completing a backup; provider deletion/retention policy is a remaining hosted
operational gate. Do not delete all old objects by prefix: retained versions may need them.

## Migrate and bootstrap

1. Approve resources, limits and scoped grants; record IDs without credentials. Keep
   LUNIA_SHOWCASE=true / deployment disabled until the reviewed deployment is prepared.
2. Use the migration-owner connection only in the operator session, with TLS. Set
   LUNIA_OPERATOR_TARGET to the exact hostname/database and LUNIA_BACKUP_REFERENCE to the
   verified backup record. Run `npm run preview:operator -- migrate`. An advisory lock
   serializes operator runs. Failure means keep CMS disabled; no automatic schema push.
3. Bootstrap with `npm run preview:operator -- bootstrap`, piping JSON containing the
   approved email/password from a secure local input/secret manager. Do not put the password
   in command arguments, terminal history, CI, chat or a file in this repository. The CLI
   holds the same lock and refuses any existing editor. Delete transient bootstrap inputs.
4. Configure branch-only CMS_ORIGIN to its stable HTTPS Vercel alias, LUNIA_CMS_BRANCH to
   the exact branch, LUNIA_STORAGE=private-blob, LUNIA_CMS_PREVIEW=true and
   LUNIA_PREVIEW_REVIEW=approved only after the operational review. VERCEL_PROJECT_ID and
   VERCEL_GIT_COMMIT_REF must match at runtime. Missing settings fail closed.
5. After explicit hosting permission, remove only this branch's deployment disable entry,
   deploy as preview and run hosted acceptance. Keep default Vercel Authentication, noindex
   and robots disallow. Never enable production builds or change the old project/domains.

The `approved` flag records an operator decision; it does not automatically prove migrations,
private-store policy, costs, or dependency safety. Enabling it is conditional on this runbook.
The local seed command remains local-only. Never run CI integration tests on the hosted DB.

## Recovery email and abuse controls

The official version-pinned Resend adapter sends only to PREVIEW_EDITOR_EMAIL. It rejects
other recipients and CC/BCC; it never redirects another user's reset link to the owner.
Use an authorized test sender if eligible before configuring any new sender domain; don't
change the old site's DNS. Disable open/link tracking in the provider. Hosted validation
must prove actual receipt, approved origin, expiry, reuse denial and recovery after lockout.
The local test substitutes the delivery API; no real email was sent.

Login uses Payload account lockout (5 attempts/10min); reset mail has atomic per-user
60-second spacing. PostgreSQL-backed limits additionally cap auth globally and per identity,
and direct upload grants per editor. Hashed keys expire; no raw email/IP is stored. Session
cookies are secure on Vercel. Provider failures are replaced with generic errors before
logging. Confirm platform request logs never capture grant/reset querystrings.

## Backup, restore and rollback

Before migrations and daily during use: quiesce CMS writes; dump the database with the
matching PostgreSQL client, then copy ALL referenced originals/derivatives and create a
hash manifest. Database export includes credentials/tokens: encrypt the export and media
archive into an approved backup destination, restrict access, and remove plaintext temp
files. The inventory command alone is not a backup. Proposed retention: seven days; target
RPO 24h/RTO 4h subject to provider choice, budget and a timed restore drill.

Restore to a NEW isolated database and private store, never over the source. Compare record
counts, relationships, every referenced object key/size/hash, login, drafts and image reads.
Only then decide any recovery switch. Record timings and delete the disposable restore
target only after validation and approved cleanup. A code rollback does not reverse schema
changes; prefer additive changes and forward repair, or restore the coordinated snapshot.
Do not claim Neon history retention or Blob object versioning until the chosen plan confirms it.

Local evidence: PostgreSQL 17 custom-format dump restored into lunia_restore_drill,
retaining one synthetic page, one editor and two migration records. This is a database
restore rehearsal, not proof of hosted coordinated database-plus-Blob restoration.
